# Local vision: first real damaged-vehicle engineering smoke

Executed 31 October 2026 (Asia/Tbilisi). This is a small engineering investigation, not an independent automotive benchmark, quality certification or auction match.

## Licensed source and method

The input is [“Altima-Accident.jpg”](https://commons.wikimedia.org/wiki/File:Altima-Accident.jpg), by [Ryanandlenny](https://commons.wikimedia.org/wiki/User:Ryanandlenny), licensed [CC BY 3.0](https://creativecommons.org/licenses/by/3.0/). Wikimedia Commons describes it as a Nissan Altima involved in an accident; the file-page metadata records the author's own work. Attribution is required. The original image was downloaded from Commons, not an auction source. It is not bundled in this repository. The image was resized and re-encoded into browser-prepared JPEG copies before the API's own metadata-stripping/re-encoding step; this is a modification of the original. Source SHA-256: `7e1e5f9098aad127f005086cf98f6627e1348d65508c517314f1f08b8adb4653`.

The image depicts visible front-corner damage; no professional inspection, repair invoice, ground-truth component annotations or independently verified vehicle history was available. A fixture Copart URL was used solely to satisfy the local API's parsed reference input; it is **not** asserted to refer to this photographed vehicle. No auction website was contacted. Findings, if any, cannot establish that vehicle's auction identity or condition.

The local `qwen3-vl:2b` model ran with Ollama bound to loopback and `OLLAMA_NO_CLOUD=1`. Requests went through the actual FastAPI `POST /api/v1/local-inspections` validation/adapter and the real local model, not a model test double. Outputs were retained locally for this investigation; no photo or inference pixels are committed here. Model inference remains experimental and no qualified human accuracy evaluation was performed.

## Actual outcomes

- First request: browser-prepared JPEG at 1600 × 1067 pixels, 320,275 bytes, SHA-256 `875c3c58feec7f455276badbd9ea6dbcc9cecad8e42e6cf5ff674220367d84cc`. After 131.12 seconds, the API returned HTTP 200 with `FAILED / INVALID_MODEL_OUTPUT`; no findings or provenance were released. The application intentionally does not expose the rejected raw response, so the specific validation failure cannot be determined from that run.
- A second identical request instrumented only this investigation to capture an eventual model response. It timed out after 180.18 seconds with `FAILED / RUNTIME_UNAVAILABLE`, with no findings or raw model response. Its timing is not a system-wide performance guarantee. The application did not alter validation or create fallback findings.
- A third diagnostic used a 768 × 512 browser-rendered copy, 94,494 bytes, SHA-256 `9704f59f0ee657db462957503157f199909a92c7865d807df78c0fd5b2a7229b`. After 102.74 seconds it returned `FAILED / INVALID_MODEL_OUTPUT`. This instrumented call captured the local model response: `done_reason=length`, 1,000 generated tokens, empty final content and 4,302 characters of separate thinking output despite the request's `think: false`. Empty content failed strict JSON validation. That output was not included in the API response or treated as findings. This explains this smaller-image attempt only; the first attempt's exact invalid-output cause remains unknown.

The installed `qwen3-vl:2b` manifest's license layer references `2b-thinking-bf16`; `/api/show` reports `qwen3-vl-thinking` renderer and parser. This corrects an earlier assumption that the tested `2b` tag was the separate Instruct model. An explicit output-limit result is now returned as `MODEL_OUTPUT_TRUNCATED`; partial text and internal thinking remain withheld. No validator or safety rule has been weakened.

The distinct official `qwen3-vl:2b-instruct` tag was then installed for one additional actual test, without changing the application's prompt or schema. Its installed manifest identifies model blob `bd2179e37645d5435e0214e5399e5997408a7e9685ba527cbb60726e6a32fd99` (1,108,016,576 bytes), projector `4dc7bc5863d7fc3ad784acf677f72f009ab5fd3758855f1996b678b621817190` (822,540,352 bytes), and the same Apache 2.0 license blob `7339fa418c9ad3e8e12e74ad0fd26a9cc4be8703f9c110728a992b193be85cb2`. Both weight blobs were SHA-256 checked. Ollama reported model digest `afc393e3572c07db0bc84aa460d928a16c75f3fbb9ca9e0dccc4fbd2dafb573e`, `qwen3-vl-instruct` renderer/parser and thinking disabled. The [upstream Instruct card](https://huggingface.co/Qwen/Qwen3-VL-2B-Instruct) declares Apache 2.0. Files remain in ignored local model storage.

The Instruct model's actual 768 × 512 image call returned after **89.96 seconds** with `FAILED / MODEL_OUTPUT_TRUNCATED`. The captured local raw response had `done_reason=length`, 1,000 generated tokens, 5,075 characters of partial final JSON and no thinking text. It repeatedly generated similar bumper wording inside a confirmation string, leaving the JSON unterminated. The adapter released no findings. This identifies a different failure from the Thinking model's exhausted thinking budget. The mere use of the Instruct tag does not fix the workflow or establish correct vehicle interpretation; no default model change was made. The partial generated text was not treated as evidence of damage accuracy.

One additional Instruct test used an experimental shorter prompt (`visible-evidence-v3`), asking for at most three findings and short, non-repeating sentences, with Ollama's documented `repeat_penalty=1.1`. It completed model generation in **62.39 seconds** (`done_reason=stop`, 494 generated tokens) and produced schema-valid JSON. However, it invented image ID `1024357896` instead of the actual `commons_altima`. The API returned `FAILED / INVALID_MODEL_OUTPUT` and withheld all findings because the evidence reference did not match. The raw output also repeated the statement “no further inspection is required for this observation” and contained contradictory/visually questionable claims, such as describing a tire as damaged or missing while its own rationale says no damage is visible. The word count and finding-count requests were not consistently followed. No result is treated as a verified damage assessment.

Because the experiment failed its identity binding and exposed unsafe advice, the unverified v3 prompt, repeat penalty and temporary provenance change were **not** adopted; production remains on `visible-evidence-v2`. The local-model response contract now additionally rejects a narrow set of “no further inspection is required/needed/necessary” wordings, with regression coverage. This guard is deliberately limited and cannot detect every unsafe statement or semantic contradiction. User-entered manual evidence is not affected. No automatic model-default switch was made. An independently reviewed vehicle cohort and further model/engineering work remain necessary.

These observed failures show that the previously successful synthetic-geometry smoke does not establish useful real-vehicle analysis. Do not call the model ready for buyer decisions on the basis of startup status or these tests. Local-model runtime output is untrusted, strict schema/evidence checks remain active, and actual correctness still needs an independently reviewed permitted vehicle cohort.
